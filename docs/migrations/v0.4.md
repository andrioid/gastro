# Migrating to v0.4

v0.4 aligns gastro with the
[Tao of Datastar](https://data-star.dev/guide/the_tao_of_datastar): **pages
are queries** (GET views, one long-lived stream per page, fat morphs) and
**commands are plain handlers** that write and return `204`. It is a clean
cutover with no deprecation shims (see [compatibility.md](../compatibility.md)):
every removed API fails to compile or fails `gastro generate` with a message,
and this guide lists the replacement for each.

Work through it in order; after each section run `go tool gastro generate`
and `go build ./...`.

| Change | What breaks | Section |
|---|---|---|
| Go 1.27 floor | `gastro generate` stops on `go 1.26` and older | [Go 1.27](#go-127) |
| Version-stamped generated code | `gastro check` reports trees from another release as stale | [Generated code](#version-stamped-generated-code) |
| Pages are GET-only | `POST`/`PUT`/… to a page get `405` | [GET-only pages](#pages-are-get-only) |
| `WithOverride` removed | compile error | [`WithHandler`](#withoverride--withhandler) |
| `Render.X` removed | compile error | [Typed rendering](#renderx--routerrender) |
| `pkg/gastro/datastar` removed | compile error | [Datastar module](#pkggastrodatastar--the-datastar-module) |
| Diagnostics fail every mode | `gastro dev`/`watch` stop on errors they used to warn about | [Diagnostics](#diagnostics-fail-in-every-mode) |
| Required props, `--typecheck-props` | opt-in; `{{ wrap }}` slot errors now fail the page | [Props](#required-props-and---typecheck-props) |
| Strict CLI arguments | `generate`/`build`/`check` reject unknown arguments | [CLI](#cli-arguments) |

## Go 1.27

Generated code uses a generic method (`Router.Render[P]`), so gastro, the
`datastar` module, and every consuming project need Go 1.27:

```diff
-go 1.26.1
+go 1.27.2
```

Update `mise.toml` / your CI toolchain to match. `gastro generate` checks the
`go` directive of your module and stops with a message naming the declared and
the required version.

## Version-stamped generated code

Generated files now start with `// Code generated by gastro vX.Y.Z. DO NOT
EDIT.` (`(devel)` for local builds). Generated code is only guaranteed to work
with the gastro release in its header: regenerate after every upgrade. If you
commit `.gastro/`, `gastro check` now also reports a tree stamped by a
different release (or by a release without a stamp) as stale, even when no
other byte differs. Pin the CLI with `go get -tool github.com/andrioid/gastro/cmd/gastro`
so the CLI and the runtime always move together.

## Pages are GET-only

Pages register as `GET <path>`. `HEAD` is served automatically; every other
method gets `405 Method Not Allowed` with `Allow: GET, HEAD`. Ambient `w` and
`r`, conditional rendering, and template-less GET pages (JSON, health checks)
are unchanged.

Move every `r.Method` branch out of the page into a handler registered with
`WithHandler`. Under Track B (v0.2–v0.3) a page could be its own command:

**Before** — `pages/tasks/[id].gastro`:

```gastro
---
import (
    "net/http"

    "myapp/app"
    "github.com/andrioid/gastro/pkg/gastro/datastar"

    Column "components/column.gastro"
)

deps := gastro.From[*app.Deps](r.Context())

if r.Method == http.MethodPost {
    if err := deps.Service.Place(r); err != nil {
        http.Error(w, err.Error(), http.StatusConflict)
        return
    }
    html, err := gastro.Render.Column(ColumnProps{Items: deps.State.Column(r.PathValue("id"))})
    if err != nil {
        http.Error(w, err.Error(), http.StatusInternalServerError)
        return
    }
    datastar.NewSSE(w, r).PatchElements(html)
    return
}

Task := deps.State.Task(r.PathValue("id"))
---
{{ wrap Layout (dict "Title" .Task.Title) }} … {{ end }}
```

**After** — the page only renders:

```gastro
---
import "myapp/app"

deps := gastro.From[*app.Deps](r.Context())
Task := deps.State.Task(r.PathValue("id"))
---
<main data-init="@get('/tasks/{{ .Task.ID }}/stream')">
    …
</main>
```

and the command is a plain handler in Go, registered next to the page:

```go
router := gastro.New(
    gastro.WithDeps(deps),
    gastro.WithHandler("POST /tasks/{id}/place", http.HandlerFunc(place)),
)

func place(w http.ResponseWriter, r *http.Request) {
    deps := gastroRuntime.FromContext[*app.Deps](r.Context())
    if err := deps.Service.Place(r); err != nil { // notifies the page streams
        http.Error(w, err.Error(), http.StatusConflict)
        return
    }
    w.WriteHeader(http.StatusNoContent)
}
```

The page's stream (`GET /tasks/{id}/stream`, also a `WithHandler` route)
re-renders the region after every change; see [sse.md](../sse.md) for the full
pattern. A command that must answer the acting user directly may still open a
short SSE response instead of returning `204`.

- `WithHandler` routes share the router's middleware (`WithMiddleware`) and
  deps: use `gastroRuntime.FromContext[T](r.Context())` (frontmatter's
  `gastro.From[T]`) or `FromContextOK`.
- Handlers that render components need the `*Router`. Declare it first and
  close over it:

  ```go
  var router *gastro.Router
  router = gastro.New(
      gastro.WithHandler("GET /board/stream", http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
          boardStream(router, w, r)
      })),
  )
  ```

- Plain HTML forms keep working: point `<form method="POST">` at a
  `WithHandler("POST /path", h)` route (Post/Redirect/Get).
- Middleware patterns stay path-only and now match `WithHandler` routes too. A
  pattern that matches neither a page nor a handler panics with "does not
  match any route".

## `WithOverride` → `WithHandler`

`WithOverride` is removed. `gastro.WithHandler(pattern, h)` takes any
`http.ServeMux` pattern, with or without a method:

- a pattern **identical** to a page's pattern overrides that page;
- a pattern identical to `GET /static/` overrides the static file server;
- any other pattern adds a route;
- a pattern that conflicts with another registration under ServeMux rules
  panics in `New()`, naming both sources.

Page patterns carry the method now, so overrides do too:

| v0.3 | v0.4 |
|---|---|
| `gastro.WithOverride("/board", h)` | `gastro.WithHandler("GET /board", h)` |
| `gastro.WithOverride("/blog/{slug}", h)` | `gastro.WithHandler("GET /blog/{slug}", h)` |
| `gastro.WithOverride("/", h)` (root page) | `gastro.WithHandler("GET /{$}", h)` |
| `gastro.WithOverride("GET /static/", h)` | `gastro.WithHandler("GET /static/", h)` |
| `mux.HandleFunc("POST /tasks/{id}/place", h)` beside `router.Handler()` | `gastro.WithHandler("POST /tasks/{id}/place", h)` (optional, but gains deps and middleware) |

Method-qualified handlers coexist with pages that method-less patterns used to
collide with: `WithHandler("POST /tasks/{id}/place", h)` registers next to the
pages `GET /tasks/{id}` and `GET /tasks/new`.

`gastro list --json` gains a `route` field with the method-qualified pattern.

## `Render.X` → `router.Render`

The generated package-level `Render` var, `Router.Render()` and the
`renderAPI` type are gone. Each component is now an exported typed value
(`gastro.Card` of type `gastroRuntime.Component[gastro.CardProps]`), rendered
through the router's generic method:

```go
func (r *Router) Render[P any](c gastroRuntime.Component[P], props P) (template.HTML, error)
```

| v0.3 | v0.4 |
|---|---|
| `gastro.Render.Card(gastro.CardProps{…})` | `router.Render(gastro.Card, gastro.CardProps{…})` |
| `router.Render().Card(gastro.CardProps{…})` | `router.Render(gastro.Card, gastro.CardProps{…})` |
| `gastro.Render.With(r).Card(gastro.CardProps{…})` | `router.Render(gastro.Card.With(r), gastro.CardProps{…})` |
| `gastro.Render.Divider()` (no `Props`) | `router.Render(gastro.Divider, gastro.DividerProps{})` |
| frontmatter `gastro.Render.Card(CardProps{…})` | frontmatter `gastro.Render(Card, CardProps{…})` |

- The result is `template.HTML`, not `string`. Convert where a string is
  needed: `sse.PatchElements(string(html))`.
- Passing another component's props fails to compile:
  `router.Render(gastro.Card, gastro.BadgeProps{})`.
- Typed props go straight to the component without the `map[string]any`
  round-trip (`MapToStruct` is only used for template `dict` calls), so
  rendering in SSE hot paths allocates less.
- In frontmatter, `gastro.Render(Card, CardProps{…})` runs per request; it
  cannot initialise package-level `var`s.
- `gastro generate` now rejects a component whose name clashes with a
  generated identifier (`New`, `Router`, `With…` options) or with another
  component's `XProps` type. Rename the component file.

## `pkg/gastro/datastar` → the `datastar` module

Datastar support moved to the nested module `github.com/andrioid/gastro/datastar`,
a facade over the official Go SDK (`github.com/starfederation/datastar-go`),
released in lockstep with gastro. Core gastro keeps no third-party
dependencies; the generic `gastroRuntime.NewSSE` stays in core.

```sh
go get github.com/andrioid/gastro/datastar@v0.4.0
```

```diff
-import "github.com/andrioid/gastro/pkg/gastro/datastar"
+import "github.com/andrioid/gastro/datastar"
```

| v0.3 | v0.4 |
|---|---|
| `sse := datastar.NewSSE(w, r)` | `sse, err := datastar.NewSSE(w, r, opts...)` — returns an error when the writer cannot flush |
| `sse.PatchSignals(map[string]any{"count": 1})` | `sse.MarshalAndPatchSignals(map[string]any{"count": 1})` |
| — | `sse.PatchSignals(rawJSON)` takes JSON bytes (`[]byte`) |
| `sse.Send("datastar-patch-elements", "elements "+html)` | `sse.Send(datastar.EventTypePatchElements, []string{"elements " + html})`, or better `sse.PatchElements(html)` |
| `datastar.PatchOption` | `datastar.PatchElementOption` |
| CDN / vendored `datastar.js` | `{{ datastarScript }}` (see below) |

Events now end with the SDK's terminator, and the module adds what the SDK
supports: `WithCompression()` (Brotli/zstd/gzip per stream), `ReadSignals`,
`ExecuteScript`, `Redirect`, `ConsoleLog`, `DispatchCustomEvent`, namespaces,
view transitions, and `WithOnlyIfMissing`. Call `ReadSignals` before
`NewSSE`.

Serve the version-matched client from your own binary instead of a CDN copy:

```go
router := gastro.New(
    gastro.WithFuncs(datastar.Funcs()),
    gastro.WithHandler(datastar.ClientPattern, datastar.ClientHandler()),
)
```

```diff
-<script type="module" src="https://cdn.jsdelivr.net/gh/starfederation/datastar@1.0.0-RC.8/bundles/datastar.js"></script>
+{{ datastarScript }}
```

The client is served at a content-hashed path with an immutable cache header.

## Diagnostics fail in every mode

Every diagnostic now carries `file:line:col`, and one run reports all of them
instead of stopping at the first. `SeverityError` diagnostics (unknown `dict`
keys, omitted required props, …) used to be warnings under `gastro dev` and
`gastro watch`; they now fail generation there too. The dev loop shows the
error in the browser through the `build-error` overlay and keeps serving the
last good build. Fix the reported positions; there is no flag to downgrade
them.

## Required props and `--typecheck-props`

Props stay optional by default. Mark a field the caller must pass with a
struct tag:

```go
type Props struct {
    Title string `gastro:"required"`
    Class string
}
```

- `gastro generate`, `check` and the dev loop reject a `dict` call that omits
  a required key.
- At render time a required field holding its zero value fails the render in
  dev mode (`GASTRO_DEV=1` / `WithDevMode(true)`) with a
  `*gastroRuntime.RequiredPropsError`, and only logs a warning in production
  (the render proceeds). `router.Render` applies the same check.
- The LSP warns only about omitted **required** props now.

`--typecheck-props` (on `generate`, `check`, `build`, `dev`, `watch`) is
opt-in in v0.4: literal `dict` values must be assignable to the field type,
and render-time conversion is strict (no `fmt.Sprintf("%v")` coercion into
string fields), with the same dev-error / production-warning policy. It
becomes the default in v0.5; turn it on now to find mismatches early.

Errors raised while rendering a `{{ wrap }}` slot now fail the page instead of
rendering an empty slot.

## CLI arguments

`gastro generate`, `build` and `check` reject unknown arguments instead of
ignoring them. `generate --project` never worked; set `GASTRO_PROJECT`
instead.
