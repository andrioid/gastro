# Migrating to v0.5

v0.5 turns on the prop type checks that were opt-in in v0.4, rejects a
Props field that collides with the `{{ wrap }}` slot, and adds live pages
to the `datastar` module. It is a clean cutover with no deprecation shims
(see [compatibility.md](../compatibility.md)): every change fails
`gastro generate` with a positioned message, and this guide lists the fix
for each.

Run `go tool gastro generate` after upgrading and work through the errors
it reports.

| Change | What breaks | Section |
|---|---|---|
| Prop type checks on by default | `generate`/`check`/`build`/dev loops fail on mistyped `dict` literals; mistyped values fail the render in dev mode | [Prop types](#prop-type-checks-are-on-by-default) |
| `--typecheck-props` removed | `unknown flag --typecheck-props` | [Prop types](#prop-type-checks-are-on-by-default) |
| `Children` Props field rejected | `gastro generate` reports the field | [`Children`](#a-props-field-named-children-is-an-error) |
| Header mutations are not response writes | nothing; a false-positive warning is gone | [Header mutations](#header-mutations-no-longer-warn) |

## Prop type checks are on by default

What `--typecheck-props` did in v0.4 is now the default on `gastro
generate`, `check`, `build`, `dev` and `watch`:

- **When generating**, literal `dict` values (strings, numbers, booleans,
  `nil`) must be assignable to the Props field type. A mismatch is an error
  at the value:

  ```
  pages/index.gastro:4:41: error: prop "Count" on component Card: cannot use "three" (untyped string constant) as int value
  ```

- **When rendering**, every `dict` value must convert to its field without
  coercion: no `fmt.Sprintf("%v")` into string fields, no parsing `"3"` into
  an `int` or `"true"` into a `bool`. A mismatch fails the render in dev mode
  (`GASTRO_DEV=1` / `WithDevMode(true)`) with a `*gastroRuntime.PropTypeError`
  and only logs a warning in production, where the lenient conversion still
  applies.

Fix the values so they match the field types:

**Before**

```gastro
{{ Card (dict "Title" "Plan" "Count" "3" "Featured" "true") }}
{{ Badge (dict "Label" .Total) }}  {{/* Label string, Total int */}}
```

**After**

```gastro
{{ Card (dict "Title" "Plan" "Count" 3 "Featured" true) }}
{{ Badge (dict "Label" (print .Total)) }}
```

When the value is right and the field is wrong, change the field type
instead (for example `Price float64` instead of `Price int`).

The `--typecheck-props` flag is gone; passing it fails with `unknown flag
--typecheck-props`. Remove it from `//go:generate` directives, `mise`/`make`
tasks and CI:

```diff
-//go:generate go tool gastro generate --typecheck-props
+//go:generate go tool gastro generate
```

To upgrade before every mismatch is fixed, opt out with
`--no-typecheck-props` on the same commands. It restores the v0.4 default
(lenient coercion, no generate-time literal check). The generated code
differs with the flag, so pass the same setting to `gastro generate` and
`gastro check`:

```sh
go tool gastro generate --no-typecheck-props
go tool gastro check --no-typecheck-props
```

## A Props field named `Children` is an error

`Children` is where gastro passes the content of a `{{ wrap }}` block, so a
Props struct that declares (or embeds) a field named `Children` used to
generate Go code that did not compile. `gastro generate` and `check` now
report the field instead:

```
components/panel.gastro:4:2: error: Props field "Children" is reserved for the {{ wrap }} slot: gastro passes the wrapped content to the component as .Children; rename the field (e.g. Items or Content)
```

Rename the field and its uses. Wrapped content stays available as
`{{ .Children }}` without a field:

**Before**

```gastro
---
type Props struct {
    Title    string
    Children []Item
}
---
```

**After**

```gastro
---
type Props struct {
    Title string
    Items []Item
}
---
```

## Header mutations no longer warn

`w.Header().Set(…)`, `.Add(…)`, `.Del(…)` and `http.SetCookie(w, …)` in page
frontmatter used to trigger "response was written but no return follows".
They only stage headers for the page response, so they are no longer treated
as writes. Drop any workaround you added for the warning; real writes
(`w.Write`, `w.WriteHeader`, `http.Error`, `http.Redirect`, `fmt.Fprint*(w, …)`,
…) still need a `return`.

## Live pages (new)

Nothing breaks; this is opt-in. `datastar.LivePages` replaces a hand-written
per-page stream (subscribe, `router.Render` a component, `PatchElements`,
loop) with one endpoint that re-renders whichever page is open through its
normal GET handler and morphs the page's live root. Renders are shared
between streams with the same page and cookies, the stream is
Brotli-compressed, and `datastar.Notifier` is a ready-made change signal.

**Before** (per page, in Go):

```go
gastro.WithHandler("GET /counter/stream", http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
    counterStream(router, w, r) // subscribe, render Counter, PatchElements, loop
})),
```

```gastro
<main data-init="@get('/counter/stream')">…</main>
```

**After** (once, for every page):

```go
live := &datastar.LivePages{Signal: &state.Changes, Root: "app", Compression: true}
router := gastro.New(
    gastro.WithFuncs(live.Funcs()),
    gastro.WithHandler(live.Pattern(), live.Handler()),
    // …
)
live.Pages = router.Handler()
```

```gastro
<body>
    {{ liveRoot .Children }}
    {{ liveScript }}
</body>
```

Commands keep writing, signalling (`state.Changes.Notify()`) and answering
`204`. A git-pm-style layout that branches on a fragment header to render
only its root can drop the branch: the stream cuts the root out of the full
page. See [Live pages](../sse.md#live-pages), and
[Client behaviour to know](../sse.md#client-behaviour-to-know) for two
Datastar client rules (patches apply only on `200`; `data-ignore-morph`
needs both sides).
