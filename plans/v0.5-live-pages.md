> Shipped: endpoint, path validation, internal re-render with the caller's
> cookies, fragment mode (`{{ liveRoot }}` + `IsFragment`), `{{ liveScript }}`,
> `Notifier`, render dedup per (path, identity), `Debounce`, Brotli. Not

## Prototype shape (git-pm `internal/web`)
- **Change signal:** a coalescing notifier (`Notifier`): one 1-buffered channel per subscriber, `Notify` is a non-blocking send to all, cancel only removes (never closes), subscribers exit on `ctx.Done()`. Driven by a ref poll (`Reftail`) and by any app state transition (auto-sync status).
- **Update endpoint:** `GET /updates?path=<page URL>` (a `WithHandler` route). Subscribes first, then loops: re-render `path` through `router.Handler()` as an internal GET (caller's `Cookie`, `X-PM-Fragment: app`), send one `PatchElements` (no selector; morph by id `app`), wait for the next signal. Always sends (no hash-and-skip). Path validated: same-origin absolute, not the stream itself. A non-200 render keeps the last good DOM.
- **Fragment render mode:** the layout checks a request-aware helper (`pmFragment`) and renders only the live root component; pages are unchanged.
- **Page root:** `<div id="app">` (an `AppRoot` component used by both modes); stream starter `data-init` on `<body>` and the error region `#pm-error` live outside it.
- **Compression:** `datastar.WithCompression()` (Brotli negotiated).

## Measured costs (10k-event fixture, M-series laptop, no -race)
- Board fragment render: ~211 ms, 13.9 MB HTML (every backlog card is rendered).
- One change, wire bytes per stream: 17.2 MB identity vs 261 KB Brotli (66×).
- Change → all streams patched: 1 stream 450 ms, 4 streams 801 ms, 16 streams 2.84 s (renders + per-stream Brotli dominate; scales ~linearly).
- Boot through cache tiers 35 ms vs warm `pm ls t` 54 ms.

## Findings for gastro
1. A `Props` field named `Children` generates uncompilable code (redeclared/duplicate key); generate should reject it.
2. `w.Header().Set(...)` in frontmatter is flagged "response was written but no return follows" — false positive.
3. Datastar client 1.0.4 applies response patches only for status exactly 200; non-2xx bodies are dropped. Commands that report failures via patches must answer 200 (status on the element).
4. `data-ignore-morph` only takes effect when *both* old and new nodes carry it, so it cannot be toggled client-side; editors must be server-rendered with it.

## Proposed v0.5 API
```go
gastro.WithLivePages(gastro.LiveConfig{
    Path:   "/_gastro/live",          // GET ?path=
    Signal: notifier,                  // interface{ Subscribe() (<-chan struct{}, func()) }
    Root:   "app",                     // id of the live root
    Compression: true,
})
```
- Gastro owns: the endpoint, path validation, internal re-render with the caller's cookies, fragment mode (`{{ liveRoot }}`…`{{ end }}` block in layouts, or `gastro.IsFragment(r)`), the starter (`{{ liveScript }}`), and a `gastro.Notifier` type.
- Render dedup: streams with the same (path, cookie-derived identity) share one render and one compressed frame per change — the measured cost is N× render+compress today.
- Optional per-page opt-out and debounce window for burst coalescing.
