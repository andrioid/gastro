## 0. What this plan covers

Three releases:

| Release | Kind | Contents |
|---|---|---|
| **v0.3.4** | fixes only | revert the stray `testing` commit, ship `d1dd023`, switch release-please so features bump the minor |
| **v0.4.0** | features + breaking cutover (one release) | Go 1.27; GET-only pages and `WithHandler`; typed `Router.Render[P]`; required props; diagnostics; `--typecheck-props` (opt-in); version-stamped generated code; compatibility policy; the `gastro/datastar` module on the official SDK with an embedded client; downstream smoke CI; migrated examples and docs |
| **v0.5.0** | features | `--typecheck-props` on by default; live pages in the datastar module, designed from git-pm's phase 12 prototype |

The central change is aligning gastro with the
[Tao of Datastar](https://data-star.dev/guide/the_tao_of_datastar): **pages are
queries** (GET views, one long-lived stream per page, fat morphs) and
**commands are plain handlers** that write and return `204`. Under Track B
(2026-05-02) pages registered for every method and branched on `r.Method`; in
git-pm, 20 of 24 pages ended up as template-less command handlers in `.gastro`
files, each opening its own SSE response to patch regions by hand.

## 1. Goals

- A page is a GET view. Commands are ordinary `http.Handler`s registered next to
  pages through one option, sharing middleware and deps.
- One typed render path from Go: `router.Render(Component, Props)`, with props
  passed as a struct (no map round-trip).
- Mistakes surface early: required props, positions on every diagnostic, all
  diagnostics per run, errors that fail the dev loop.
- Datastar support that tracks the protocol: the official Go SDK on the server,
  a version-matched client served by gastro.
- Releases that downstream projects can pin: a version in generated code, a
  written compatibility policy, and a CI signal when gastro breaks its main
  adopter.

## 2. Anti-goals

- No deprecation shims. Breaking changes are clean cutovers with a migration
  guide (§4.3).
- No new authoring concepts in templates. The required tag lives in Go struct
  tags; routing lives in Go options.
- Core `github.com/andrioid/gastro` gains no third-party dependencies. The SDK and
  its tree live only in the separate `datastar` module.
- No method directives on pages (proposal 3 is dropped), and no component
  DOM-target API (proposal 4 is dropped): page-level fat morphs need neither.
- Live pages are **not** designed in this repo first. They are prototyped in
  git-pm (phase 12) and land here in v0.5.0.

**Decided while writing this plan** (review before Phase 4 starts):

- `Component[P]` lives in `pkg/gastro`. The generated package exports one value
  per component (e.g. `gastroweb.BoardColumn`, of type
  `gastro.Component[BoardColumnProps]`). Type inference makes calls read
  `router.Render(gastroweb.BoardColumn, gastroweb.BoardColumnProps{…})`.
- The datastar module cannot construct a project's generated `Option`s (those are
  generated per project), so it exports building blocks, which apps wire in:
  `datastar.ClientPattern`, `datastar.ClientHandler()`, and `datastar.Funcs()`.
- Lockstep releases use release-please's `linked-versions` plugin. The submodule
  is tagged `datastar/vX.Y.Z` (Go's tag format for nested modules); the root
  keeps `vX.Y.Z`.

### 4.2 Phase 1 — Go 1.27 everywhere

- `go.mod`, `mise.toml` (`go = "1.27.x"`), all seven `examples/*/go.mod`,
  `internal/scaffold/template/go.mod.tmpl`.
- `gastro generate` checks the consumer module's `go` directive and errors
  clearly when it is below 1.27, since generated code will use generic methods
  (Phase 4). Without this the user gets a compiler error inside `.gastro/`.

**Acceptance:** a project with `go 1.26` fails `gastro generate` with a message
naming the required version; the full suite is green on 1.27 with `-race`.

### 4.3 Phase 2 — Version stamp and compatibility policy

- The generated header becomes `// Code generated by gastro vX.Y.Z. DO NOT EDIT.`.
  The version comes from the binary's build info (module version under
  `go tool gastro`; `(devel)` for local builds).
- `docs/compatibility.md`:
  - pre-1.0, fixes bump the patch, and features and breaking changes bump the
    minor;
  - every breaking change ships with `docs/migrations/vX.Y.md` and a
    `BREAKING CHANGE` footer;
  - no deprecation shims;
  - generated code is only guaranteed to work with the gastro version stamped in
    its header.

**Acceptance:** two generations with different binaries differ only in the
header line; `gastro check` reports a version mismatch between the binary and an
existing `.gastro/` tree as stale.

### 4.4 Phase 3 — Diagnostics (absorbs ROADMAP "Promote dict-key SeverityError …")

- Every diagnostic carries `file:line:col`, and every diagnostic in the project
  is reported in one run. Today the first error stops the run.
- `SeverityError` diagnostics fail **non-strict** generation too:
  `runGenerate(false)` (`cmd/gastro/main.go:604`, `cmd/gastro/watch.go:505`). The
  dev loop shows the error through the existing `build-error` devreload event
  instead of serving a page that crashes at runtime.

**Acceptance:**
- A project with three bad `dict` keys in two files reports all three, with
  positions, and exits non-zero.
- Under `gastro watch`, introducing one bad key emits `build-error` and keeps
  serving the previous good build.

### 4.5 Phase 4 — Typed rendering: `Router.Render[P]` (closes ROADMAP "Typed `Render` bypassing …")

- `pkg/gastro`: `type Component[P any] struct{ … }`, wrapping an unexported
  typed render function.
- Generated: one exported `Component[XProps]` value per component, and
  `func (r *Router) Render[P any](c gastro.Component[P], props P) (template.HTML, error)`.
  Typed props go straight to the component; `MapToStruct` remains only for
  template-side `dict` calls.
- Remove the generated `renderAPI`, the package-level `Render` var,
  `Router.Render()`, and `__gastro_active` (its only reader is the package-level
  `Render`).
- LSP shadow workspace (`internal/lsp/shadow/workspace.go` `routerStub`): replace
  the `renderAPI` stubs with the component values and the generic method.

**Acceptance:**
- A component rendered through `Render` produces byte-identical HTML to the same
  component rendered from a template `dict`.
- A benchmark shows `Render` doing no map allocation for props.
- `Render(gastroweb.Card, gastroweb.BadgeProps{})` fails to compile.
- The LSP shadow audit reports zero diagnostics across `examples/`.

### 4.6 Phase 5 — Required props (rewrites ROADMAP "Optional Props fields …")

- `gastro:"required"` on a Props field.
- **Generate time:** a `dict` call that omits a required key is an error, with
  its position (reuses the `ValidateDictKeysFromAST` missing-prop branch, limited
  to required fields).
- **Render time:** a required field holding its zero value fails the render in
  dev mode (`WithDevMode` / `GASTRO_DEV=1`) and logs a warning via `log/slog` in
  production, then renders. The same check applies to `Render[P]`.
- LSP missing-prop warnings are limited to required fields (today every field
  warns: `internal/lsp/template/completions.go:631`).

**Acceptance:**
- An omitted required key fails `gastro generate`, `check`, and the dev loop.
- A present-but-empty required prop errors in dev mode and only logs in
  production (two tests, one per mode).
- Non-required fields never warn.

### 4.7 Phase 6 — `--typecheck-props` (opt-in)

- **Generate time:** literal `dict` values (string, number, bool, `nil`) must be
  assignable to the field type.
- **Render time:** strict assignment, with no silent coercion (today
  `setStringField` turns any value into a string through `fmt.Sprintf("%v")`). A
  mismatch follows D6: an error in dev mode, a logged warning in production.
- Flag on `generate`, `check`, `watch`, `dev`, and `build`.

**Acceptance:**
- `dict "Count" "three"` into `Count int` fails generate with the flag and passes
  without it.
- A runtime mismatch errors in dev mode with the flag on.

### 4.8 Phase 7 — GET-only pages and `WithHandler` (supersedes Track B routing)

- Generated routes register as `GET <path>` (`internal/compiler/compiler.go`
  route loop around L1527). ServeMux then serves HEAD and answers other methods
  with `405` and an `Allow` header.
- `WithHandler(pattern, h)`:
  - takes any ServeMux pattern, with or without a method;
  - a pattern identical to a page's (`GET /x`) or to the static prefix
    (`GET /static/`) overrides it;
  - any other pattern adds a route;
  - a conflicting registration panics in `New()` with a message naming both
    sources.
  - `WithOverride` is removed.
- `WithMiddleware` keeps path-only patterns and applies to page routes **and**
  `WithHandler` routes. Validation (`PatternMatchesAnyRoute`) probes both.
  `MiddlewareApplies` compares the path part of method-qualified routes.
- Deps injection reaches `WithHandler` handlers (`gastro.From[T](r.Context())`).
- `gastro list` prints methods, and marks `WithHandler` routes when they are
  known at generate time.
- Frontmatter keeps ambient `w` and `r`. Template-less GET pages (JSON
  endpoints, health checks) remain valid.

**Acceptance:**
- `POST /page` → 405 with `Allow: GET, HEAD`, and `HEAD /page` → 200 with no
  body.
- `WithHandler("POST /tasks/{id}/place", h)` coexists with the page
  `GET /tasks/{id}` and with `GET /tasks/new` (the combination that panics with
  method-less patterns).
- `WithHandler("GET /x", h)` overrides page `/x`.
- Middleware registered at `/` wraps both pages and handlers.
- `gastro.From[T]` works inside a handler.

### 4.9 Phase 8 — `github.com/andrioid/gastro/datastar` module

- A new module in `datastar/` with its own `go.mod` (depends only on the SDK
  tree from D14). `pkg/gastro/datastar` is removed; the generic `gastro.SSE`
  stays in core.
- API, a facade over the SDK:
  - `NewSSE(w, r)` returns an error instead of panicking when the initial flush
    fails;
  - `PatchElements(html, opts...)` with `WithSelector`, `WithMode`, and the
    SDK's namespace, view-transition, and only-if-missing options;
  - `PatchSignals([]byte)` and `MarshalAndPatchSignals(any)`;
  - `RemoveElement`, `ReadSignals(r, &v)`, `ExecuteScript`, `Redirect`,
    `ConsoleLog`, `DispatchCustomEvent`;
  - Brotli/gzip compression through the SDK;
  - raw `Send` follows the SDK's signature.
- Embedded client: `datastar.js` matching the SDK's protocol version, served by
  `ClientHandler()` at `ClientPattern` (`GET /_gastro/datastar/<sha256-prefix>.js`,
  `Cache-Control: immutable`). `Funcs()` provides `{{ datastarScript }}`, which
  renders the `<script type="module">` tag.
- release-please: second package `datastar` (component `datastar`, tag
  `datastar/vX.Y.Z`), `linked-versions` with the root package.
- Docs: `docs/sse.md` rewritten around CQRS (one stream per page, commands
  returning `204`); `docs/compression.md` points at the module.

**Acceptance:**
- SSE output for each event type matches the SDK's own encoding.
- A body containing `\r\n` cannot inject SSE fields (the existing guard's test,
  ported).
- The client path changes exactly when the embedded bytes change.
- `{{ datastarScript }}` renders that path.
- `go list -m all` in core lists no new modules.

- `--typecheck-props` on by default (`--no-typecheck-props` to opt out).

## 5. Risks

| Risk | Mitigation |
|---|---|
| Go 1.27 floor excludes consumers on older toolchains | The Phase 1 version check gives a clear message; the migration guide states the floor |
| Apps register `WithHandler` patterns that conflict under ServeMux rules | `New()` panics with both sources named; documented with the `GET /tasks/new` vs `GET /tasks/{id}` example |
| The SDK's dependency tree grows | Isolated in the datastar module; core's `go list -m all` is asserted in CI |
| Nested-module tagging mistakes in release-please | A dry-run release PR before v0.4.0; `go get github.com/andrioid/gastro/datastar@v0.4.0` smoke step |
| Render-time required checks surprise production users | Production only logs (D6); the migration guide explains the dev-mode error |
